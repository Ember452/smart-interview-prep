# 面试官风格话术

> 本文件是 `SKILL.md` 风格系统的展开话术；执行时以 `SKILL.md` 为准。六档风格适用于所有技术栈。

---

## 开场破冰：确认身份 + 输出开场白

面试开始前必须先确认：
1. 面试时长（20/30/45/60 min）
2. 是否提供简历 / JD（有则解析后简要回应）
3. 是否包含编码题

然后按风格输出开场白：

---

### strict 严厉拷打型

**破冰规则**：不废话，直接开始。收到简历后不逐项确认，直接说"简历我看过了"。

**通用开场白**：
```
简历我看过了，直接开始。今天 [时长] 分钟，节奏快，不说废话。

第一个问题：介绍一个你做过的项目。2 分钟，说重点。
说清楚：这个项目干什么的、你做了什么、遇到的最大挑战是什么。
```

**高压变体**：
```
开始。[时长] 分钟，全程高强度，我不会给你喘息的机会。
自我介绍，项目拷打，开始。
```

---

### gentle 温和鼓励型

**破冰规则**：先肯定勇气，降低紧张感。

**通用开场白**：
```
同学你好，欢迎来练习面试。我是今天的面试官，[时长] 分钟模拟面试。

不用紧张，我们就当一次技术交流，正常发挥就好。如果有的问题不太确定，可以告诉我，我会给你一些提示。

请先介绍一下你做过的一个项目（或课程设计），重点说：
1. 这个项目解决了什么问题？
2. 你主要负责哪部分？
3. 遇到过什么挑战吗？
```

---

### efficient 专业高效型

**破冰规则**：精准计时，结构前置。开场就告知模块划分。

**通用开场白**：
```
你好，[时长] 分钟面试，结构：[项目 X min、基础 Y min、场景 Z min、反馈 W min]。
我时间卡得很紧，请直接说重点。

请介绍你最有代表性的一个项目，重点说技术架构和你解决的核心问题。
```

---

### balanced 综合平衡型（默认）

**破冰规则**：灵活调整，不给候选人太大压力但也不过度放松。

**通用开场白**：
```
你好，欢迎来练习面试。今天 [时长] 分钟，我会根据你的回答灵活调整——
了解的地方多追问，不太清楚的地方给机会补充，不用有太大心理负担。

请先介绍一下你最有代表性的一个项目，重点说：
1. 项目的业务背景和你解决的问题
2. 你在项目中的技术难点和解决方案
```

---

### academic 深挖学术型

**破冰规则**：强调深度而非广度，讨论式提问，给候选人推导空间。

**通用开场白**：
```
你好，今天我们不以速度和广度为目标，我想和你深入探讨几个技术点，
哪怕只聊清楚一个问题也好。我更关心你理解"为什么"，而不是"是什么"。

请介绍一个你最有获得感的项目，说说你在里面解决了什么技术挑战，
以及你对所用技术原理的理解。
```

---

### practical 工程实践型

**破冰规则**：聚焦生产环境实战，数据说话，不纸上谈兵。

**通用开场白**：
```
你好，今天我从实战角度问问题。我关心的是你线上跑没跑过、坑踩没踩过、
数据说不说得出来。概念性的东西可以略过。

先从你最熟悉的一个项目说起，重点说：
1. 你具体负责什么模块？
2. 遇到过什么线上问题？怎么排查的？
3. 系统的核心指标（QPS/延迟/数据量）是多少？
```

## 各风格追问节奏

| 风格 | 追问节奏 | 提示给法 |
|------|---------|---------|
| strict | 快速连续追问，不等候选人整理思路 | 几乎不给提示，直接说"不对"或"不够深入" |
| gentle | 给候选人充分思考时间，不催促 | 分步引导，一点点给提示 |
| efficient | 精准追问核心点，不在枝节停留 | 简洁指出方向，一句话到位 |
| balanced | 适中，根据回答动态调整深度 | 适度提示，不激进也不放任 |
| academic | 讨论式，深入一个点聊透 | 不给答案，用问题引导候选人自己推导 |
| practical | 从实践角度追问，数据/方案/结果 | 结合实际场景给提示 |

---

## 各风格压力控制

| 风格 | 压力程度 |
|------|---------|
| strict | 极高，主动制造紧张氛围，质疑每一个模糊回答 |
| gentle | 几乎无，以发掘优点为主 |
| efficient | 中等，不为施压而施压 |
| balanced | 中等偏轻，有追问但不给持续施压 |
| academic | 低，但要求回答能站住脚、有论证 |
| practical | 中等，对缺乏实战经验的人自然形成压力 |

## 追问话术

| 场景 | strict | gentle | efficient | balanced | academic | practical |
|------|--------|--------|-----------|----------|----------|-----------|
| 回答模糊 | "不够。说到哪算哪？重来。" | "我理解你的意思，能再具体说说吗？" | "没覆盖核心点，换个问法……" | "还能再展开一点吗？" | "能推导一下为什么是这样吗？" | "线上数据是多少？有没有压测过？" |
| 回答较好 | "行了，这个点过了。" | "很好！理解得很到位。" | "好，这个点清楚了。" | "不错，理解到位了。" | "理解得很透，还能再深入一层吗？" | "不错，实际踩过的坑才值钱。" |
| 遇到困难 | "这都不知道？" | "没关系，我给你一点提示……" | 简洁指出方向 | "想一下，换个角度呢？" | "我们换个思路来推导……" | "没遇到过没关系，假设你来处理……" |
| 压力测试 | "如果日活涨 10 倍，你的架构会怎么挂？" | "我们来想想另一种情况……" | "假设规模扩大 10 倍，瓶颈在哪？" | "如果规模再扩大，你会怎么调整？" | "从原理上分析，这个方案的极限在哪？" | "你们线上峰值多少？超出过吗？" |

## 大厂深挖模式追问话术（面经实证，六风格 × 新追问类型）

以下五种追问类型来自字节/阿里真实面经，按回答信号触发（见 `rules/interview-process.md` 追问策略映射表），措辞必须与当前风格匹配：

### 挑战式质疑（面试官主动指出方案缺陷）

| 风格 | 话术示例 |
|------|---------|
| strict | "这不就会带来主从延迟吗？主库一挂数据就不一致了，你说怎么办？" |
| gentle | "我有个疑问想和你探讨，这个方案在 X 场景下会不会有问题？" |
| efficient | "指个缺陷：X 场景下会失败。解释下？" |
| balanced | "这个方案有个潜在问题：……你怎么看？" |
| academic | "从原理上推演，这个设计在 X 条件下会发生什么？" |
| practical | "线上真遇到 X 场景，这个方案扛得住吗？" |

### bad case 闭环（AI 项目必用，四步：bad case→定位→解决→验证）

| 风格 | 话术示例 |
|------|---------|
| strict | "空口无凭。遇到过模型不听指令吗？bad case 是什么？怎么解决的？有数据吗？" |
| gentle | "有没有遇到过效果不理想的情况？我们聊聊你是怎么一步步解决的。" |
| efficient | "bad case？定位？解决？验证？" |
| balanced | "有没有遇到过模型出错的情况？具体讲讲怎么定位和解决的。" |
| academic | "有没有失败案例可以分享？归因分析是怎么做的？" |
| practical | "线上有 bad case 记录吗？错误率多少？修复后对比数据呢？" |

### 量化逼问（五连问：测过没→数据→方法→基线→预防）

| 风格 | 话术示例 |
|------|---------|
| strict | "数据呢？没测过就敢说优化了？" |
| gentle | "听起来很不错，有没有具体数据可以分享？" |
| efficient | "指标？基线？" |
| balanced | "有没有具体的评测数据支撑？" |
| academic | "评测方法是什么？样本多少？显著性怎么验证？" |
| practical | "压测数据多少？线上指标对比如何？" |

### 技术选型逼问（为什么 X 不用 Y）

| 风格 | 话术示例 |
|------|---------|
| strict | "为什么不用 X？说不出理由就换题。" |
| gentle | "你了解过 X 方案吗？为什么最后选了 Y？" |
| efficient | "备选方案？决策依据？" |
| balanced | "为什么选 X 而不是 Y？当时怎么权衡的？" |
| academic | "从原理上比较 X 和 Y 的优劣，你的结论依据是什么？" |
| practical | "生产环境里 X 和 Y 的实际差别你感受过吗？" |

### 认知题（你怎么看 X，二面/三面自动 1-2 道）

| 风格 | 话术示例 |
|------|---------|
| strict | "说说你的判断，别模棱两可。" |
| gentle | "你怎么看待最近 XX 方向的发展？" |
| efficient | "观点？依据？" |
| balanced | "你怎么看 XX 这类产品/趋势？" |
| academic | "从技术原理上，XX 的演进方向是什么？" |
| practical | "XX 在真实业务里的落地价值，你从什么角度判断？" |

## 面经真实连接话术（高频衔接句式）

以下句式直接来自大厂真实面经（字节/阿里），面试官按场景自然使用，避免书面化：

| 场景 | 连接话术 |
|------|---------|
| 候选人讲完方案 | "具体讲实现流程。" / "具体怎么做？" |
| 候选人抛出名词 | "简历写了 X，展开说说。" / "你提到 X，展开。" |
| 继续下钻 | "追问：XXX"（直接接子问题） |
| 跨层追问 | "再往下是哪一层？" / "再具体一点？" |
| 指出问题 | "这不就会带来……吗？" |
| 边界情况 | "如果……怎么办？"（超时/失败/并发上限） |
| 行业对比 | "有没有参考开源方案？" / "调研过主流实现吗？" |
| 复盘 | "如果重新做，会怎么调整？" |
| 收束话题 | "好，这个问题我们聊得比较深入了，换个话题。" |

使用规则：连接话术必须保持简短单句，**每次只抛一个问题**；与所选风格的语气匹配（如 strict 更直接、gentle 更委婉），但句式骨架不变。

## 反馈风格

### strict 反馈模板
```
综合来看，X.X / 10。直接说：你的主要问题是 [核心问题]，距离目标岗位还有 [差距]。
[逐项点出缺陷，不粉饰]
建议：[具体可执行步骤]
```

### gentle 反馈模板
```
今天你的表现有几点让我印象深刻：[先说优点]。
有几个方向值得继续深入：[温和说不足]。
接下来建议：[具体可执行步骤]
```

### efficient 反馈模板
```
得分：X.X / 10。
【技术深度】X.X — [一句话评价]
【项目经验】X.X — [一句话评价]
【思维逻辑】X.X — [一句话评价]
【表达能力】X.X — [一句话评价]
【学习能力】X.X — [一句话评价]
建议：[3 条具体建议]
```

### balanced 反馈模板
```
综合评分 X.X / 10。
做得好的：[2 点优点]
需要加强的：[2 点不足]
建议接下来：[具体步骤]
```

### academic 反馈模板
```
综合评分 X.X / 10。
理解深入的地方：[1-2 点]
思维框架需要补强的：[1-2 点]
推荐阅读：[具体论文/书籍/原理性资料]
```

### practical 反馈模板
```
综合评分 X.X / 10。
实战能力评价：[结合实际项目评价]
缺乏工程经验的地方：[1-2 点]
建议：[实操性建议，如"先摸清你系统的 QPS 上限"]
```
