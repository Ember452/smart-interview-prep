# 评分 Rubric 展开版（1-10 分制）

> 本文件是 `SKILL.md` 中评分系统的展开锚点。执行时以 `SKILL.md` 为准；SKILL.md 仅保留维度权重，综合得分公式、计算示例、报告话术可按本文件执行。

---

## 维度与权重

所有候选人使用统一权重，不按背景区分：

| 维度 | 权重 | 考察重点 |
|------|------|---------|
| 技术深度 | 25% | 原理理解深度、源码/协议细节、trade-off 解释能力 |
| 项目经验 | 25% | 项目规模、贡献清晰度、量化成果、线上问题处理 |
| 系统设计能力 | 15% | 架构设计、容量规划、扩展性、高可用、数据一致性、权衡取舍 |
| 思维逻辑 | 15% | 问题拆解路径、表达条理性、追问自洽性 |
| 表达能力 | 10% | 表达流畅度、术语准确度、类比辅助能力 |
| 学习能力 | 10% | AI 工具使用、技术趋势跟进、学习方法体系 |

---

## 等级锚点（通用）

| 等级 | 分数 | 标准 |
|------|------|------|
| 优秀 | 9-10 | 核心概念准确、细节充分、能解释 trade-off 与选择理由，追问回答自洽 |
| 良好 | 7-8 | 核心概念正确，能回答"为什么"，但追问到更深层时回答偏浅 |
| 一般 | 5-6 | 基本概念正确，停留在使用层面，缺乏系统级或深层理解 |
| 不足 | 3-4 | 概念模糊、回答碎片化、无法形成连贯逻辑 |
| 较差 | 1-2 | 核心概念理解错误、偏题、无法承接追问 |

## 维度级锚点

### 技术深度
- 9-10：能讲清源码/底层实现/协议细节，有系统性理解
- 7-8：核心原理正确，能回答"为什么这样设计"
- 5-6：知道基本概念，停留在使用层面
- 3-4：概念模糊，无法描述
- 1-2：核心概念错误，完全不了解

### 项目经验
- 9-10：真实生产级项目，能说清架构选型权衡、线上问题处理、量化成果
- 7-8：有一定规模项目，能描述技术难点和自己的贡献
- 5-6：有项目但描述偏平、缺少数据支撑
- 3-4：项目说不清楚，贡献模糊
- 1-2：无真实项目经验

### 系统设计能力
- 9-10：架构设计完整，容量估算精准，能系统性地分析扩展性和高可用，trade-off 论述充分
- 7-8：能给出合理架构，覆盖主要组件，但部分细节或边界情况考虑不够
- 5-6：能画出基本架构图，但缺少容量估算、数据一致性考量
- 3-4：架构思路碎片化，无法形成完整设计，关键组件遗漏
- 1-2：无法给出有效的系统设计思路

### 思维逻辑
- 9-10：层层拆解问题，分析路径完整，前后自洽
- 7-8：逻辑连贯，能有条理地表达观点
- 5-6：基本能回答，但思路有时跳跃
- 3-4：思维混乱，前后矛盾
- 1-2：无法形成有效回答

### 表达能力
- 9-10：表达流畅，专业术语准确，能用类比辅助解释
- 7-8：表达清晰，术语基本准确
- 5-6：能表达基本意思，但有时词不达意
- 3-4：表达困难，需多次追问才能理解
- 1-2：无法有效沟通

### 学习能力
- 9-10：主动探索 AI 工具、跟进技术趋势、有学习方法体系
- 7-8：了解 AI 工具，有一定使用经验
- 5-6：了解 AI 工具但使用较少
- 3-4：对新工具/新技术几乎不了解
- 1-2：抵触学习

## 综合得分计算

```
综合得分 = 技术深度 × 0.25
         + 项目经验 × 0.25
         + 系统设计能力 × 0.15
         + 思维逻辑 × 0.15
         + 表达能力 × 0.10
         + 学习能力 × 0.10
最终分数保留 1 位小数
```

### 计算示例

候选人各项打分：技术深度 8 / 项目经验 7 / 系统设计能力 7 / 思维逻辑 7 / 表达能力 8 / 学习能力 6

```
综合得分 = 8 × 0.25 + 7 × 0.25 + 7 × 0.15 + 7 × 0.15 + 8 × 0.10 + 6 × 0.10
        = 2.0 + 1.75 + 1.05 + 1.05 + 0.8 + 0.6
        = 7.3 / 10
```

### 报告必须展示计算过程（遵循度加固，强制）

生成报告时，综合得分**不得直接给结果**，必须按以下三步显式输出（对应 `templates/full-report.md` 的"评分计算"块）：

1. **先列六个维度原始分**（分项评分表）
2. **再逐项写出带数字的加权项**（如 `技术深度 8 × 0.25 = 2.0`），逐行相加
3. **最后给出求和结果**，且与报告顶部/摘要处的综合分一致

目的：逼模型实际走一遍算术，避免“拍脑袋”给总分导致加权算错、或星级与分数不自洽。若某题因"查看答案/不会"不计分，在计算块注明受影响的维度取样口径。

## 报告呈现规范

- **逐题评级**：用 ⭐⭐⭐⭐⭐ 直观表示（1-5 档，对应分数段）
- **分项评分**：用 1-10 分制 + 真实评价（不含客套话）
- **综合得分**：保留 1 位小数，附 0-10 分制
- **反馈措辞**：必须与当前面试官风格一致（见 `reference/interviewer-styles.md`）

## 行为面试 / 软素质评分归属

行为面试**不单设权重维度**（保持 6 维度权重合计 100%），其表现按内容映射到既有维度：

| 行为表现 | 计入维度 |
|---------|---------|
| 问题拆解、决策逻辑、复盘自洽 | 思维逻辑 |
| 表达条理、STAR 结构清晰度 | 表达能力 |
| 主动学习、反馈接受度 | 学习能力 |
| 真实项目中的 Ownership、量化结果 | 项目经验 |

报告的「录用建议」章节应综合行为表现给出**软素质定性观察**（如"Ownership 强 / 抗压一般 / 复盘偏浅"）。

## 录用结论与定级映射（报告「录用建议」章节）

真实大厂面试后，候选人最关心两件事：**能不能过、能定几级**。报告必须给出面试官视角的结论。

### 综合得分 → 录用倾向

| 综合得分 | 录用倾向 | 含义 |
|---------|---------|------|
| 8.5-10 | 强烈推荐（Strong Hire） | 明显超出岗位预期，可冲更高职级 |
| 7.0-8.4 | 推荐（Hire） | 符合岗位要求，可进入下一轮 / 给 offer |
| 5.5-6.9 | 待定（Lean Hire / 存疑） | 有亮点但短板明显，需下一轮交叉验证 |
| 4.0-5.4 | 不推荐（No Hire） | 关键能力不足，本轮难以通过 |
| < 4.0 | 明确拒绝（Strong No Hire） | 多维度不达标，与岗位差距大 |

### 定级参考（通用映射，仅供参考）

结合综合得分、项目复杂度与系统设计表现，给出一个**大致职级带**（不硬挂具体公司职级，用“约等于”措辞）：

| 综合表现 | 大致定位（参考） |
|---------|----------------|
| 基础扎实、项目偏轻、系统设计弱 | 初级 / 校招（约 P5 / L3-L4 / 初级工程师） |
| 能独立负责模块、项目清晰、有基本设计能力 | 中级（约 P6 / L4-L5 / 2-4 年） |
| 能主导复杂项目、系统设计成熟、有技术影响力 | 高级（约 P7 / L5-L6 / 5 年+） |
| 架构视野宽、trade-off 通透、跨团队影响力 | 专家 / 资深（约 P8+ / L6+） |

### “若本轮挂了”归因（报告必需）

面经最有价值的部分是复盘“为什么被拒”。报告必须给出 **1-2 条最可能导致本轮不通过的关键原因**（如“项目深度不足、追问到底层即卡住”“系统设计缺容量估算与一致性考量”），即使结论是“推荐”也应指出最弱项。

## 反问环节评估

反问质量不计入加权得分，但在报告「录用建议」中作为**求职诚意与思考深度的参考信号**（分档：优秀/一般/偏弱，见 `reference/behavioral-questions.md`）。
