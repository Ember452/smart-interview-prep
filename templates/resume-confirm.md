## 简历风险点预检（强制，面试开始前必须输出）

解析确认块之后、配置确认块之前，**必须**增加一节「⚠️ 简历风险点预检」。这是真实面试官第一眼会盯的地方，提前暴露让候选人有机会自圆其说或补数据，避免面试中途被打个措手不及。

### 预检规则

逐项扫描简历，命中以下信号则列出（未命中则写"未发现明显风险点"）：

| 风险信号 | 预检表述示例 |
|---------|------------|
| 空量化指标（“达 %”“P95 ms”“提升 X 倍”后无数字） | “`recall@3 达 %` 指标为空——面试官会当场要数据；建议要么真测后补上，要么坦诚改为‘未做评测’” |
| 量化数字无来源/口径不明 | “`20 并发压测` 数据口径是什么（压测工具/时长/机器配置）？面试官大概率会追问测量方法” |
| 个人/课程项目堆分布式组件（锁、MQ、注册中心、多实例） | “单实例部署为什么需要分布式锁/Single-flight？需准备好‘部署规模’与‘为何要分布式设计’的回答” |
| 名词堆砌无细节支撑（一句话罗列 5+ 技术名词） | “`Spring AI + LiteFlow + Redis + MongoDB + ES` 密集堆叠，需保证每个名词都能被追问 2 层” |
| 时间线/角色/规模矛盾 | “项目周期 4 个月且标注‘个人实现’5 个复杂模块，真实面试官会怀疑分工与真实性” |
| AI 项目无评测/无 bad case/无对标 | “AI 项目缺评测数据与 bad case 复盘，面试官默认走 bad case 闭环 + 量化逼问” |

### 输出格式

```
⚠️ 简历风险点预检（真实面试官视角，提前防御）
1. [空量化指标]：“recall@3 达 %”缺数字，面试官会当场要数据…
2. [规模存疑]：个人项目使用分布式 Single-flight，需准备“部署了几台机器”的回答…

建议：面试中要么给出真实数据，要么坦诚说明未测/未上线——不要含糊。
```

### 执行规则

- 风险点**只提示、不判死**：允许候选人解释或修正（如“指标是我漏填了，实际是 XX”），修正后按新信息面试
- 预检结果记入 `weaknesses_observed`，用于指导后续出题方向
- 预检措辞保持与面试官风格一致（`strict` 直接点名，`gentle` 委婉提示）
